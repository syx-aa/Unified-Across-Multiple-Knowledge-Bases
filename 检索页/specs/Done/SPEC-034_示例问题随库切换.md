# SPEC-034 · 示例问题随知识库切换

> 状态：Done ｜ 日期：2026-10-25 ｜ 负责人：项目负责人（定方案） / AI（实施）
> 上游：SPEC-033（多知识库切换） ｜ 关联文件：`build/build_data.py`、`index.html`

## 1. 背景（Why）

SPEC-033 让页面能在多个知识库间切换，但**示例问题引导还停留在世界杯库**：

```javascript
var EXAMPLES = [
  '阿根廷 26 人大名单都有谁？',
  '2026 世界杯夺冠热门有哪些？',
  '央视拿下转播权花了多少钱？',
  '梅西',
  '小组赛赛程怎么安排？'
];
```

用户切到「企业内部项目文档」后，页面上仍然提示去问「梅西」「2026 世界杯夺冠热门」——
**这些词在企业库里根本不存在，点了必然零命中**。

这不是 cosmetic 问题：示例引导是用户理解「这个库能问什么」的第一入口，
引导错了等于把人往死路上带。

## 2. 需求（What）

每个知识库自带一套示例问题，**切换库时示例随之切换**。

## 3. 方案选型（决策记录）

负责人问「A / B / C 是什么意思」，已解释并确认走 **A**：

| | 方案 | 示例存在哪 | 新增第 4 个库时 |
|---|---|---|---|
| **A**（选定） | 跟着数据文件走 | 每个库目录下 `examples.txt`，构建时读进 `meta.examples` | 丢一个 txt 进去，**不动代码** |
| B | 前端硬编码 | 写死在 `index.html` 的 `LIB_EXAMPLES` | 要改前端代码 |
| C | 自动生成 | 从文档标题自动拼 | 全自动，但质量差 |

**不选 C 的原因**：企业库文档命名是
`中信证券_AI质检系统_项目进度汇报_20250903` 这种格式，自动拼出来的示例不像人话。

**A 的一个附带好处**：示例存在数据文件里，所以**双击 `file://` 打开时也能切换**
——与负责人「双击和起服务两个都要」的要求一致。

### 一个必须说明的架构点

把示例放进 `data-<db>.js` 之后，切换库就**不只是改一个检索参数了** ——
前端的 `D`（docs / terms / aliases / meta）也必须跟着换，否则：

- 示例问题取自 `D.meta.examples` ❌
- 离线自检用的 `D.terms` / `D.aliases` ❌
- 降级路径的本地检索用 `D.docs` ❌

所以 `switchLib()` 改成**带 `?db=` 的 URL 重新载入页面**，而不是原地改状态。
`file://` 下 query 同样保留，双击打开也能切。
