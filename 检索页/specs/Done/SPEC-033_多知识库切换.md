# SPEC-033 多知识库切换

> 状态：Done ｜ 优先级：P1 ｜ 归属：数据层 + 检索层 + 前端 ｜ 更新：2026-10-25
> 设计方案：[`设计方案_多库切换.md`](../../设计方案_多库切换.md)


## 1. 需求（Spec）

现在页面只能检索单一知识库（世界杯）。`LLM Wiki/LLM Wiki/` 下实际存在三个知识库：

| 目录 | Raw | entity | concept | source | Wiki 体积 | 状态 |
|---|---|---|---|---|---|---|
| `2、小红书AI帖子` | 85 | 25 | 25 | 85 | 201 KB | 完整 |
| `3、世界杯` | 77 | 62 | 14 | 72 | 162 KB | 完整（当前接入） |
| `4、企业内部项目文档` | 104 | 125 | 102 | **0** | 12 KB | ⚠️ Wiki 为空占位 |

本 Spec 要增加**知识库切换器**：用户在多个库之间切换后，检索范围、实体/别名表、
向量索引、答案来源全部限定在所选库内。

**边界（不做什么）**：

- 不做跨库联合检索（一次只查一个库）
- 不自动判断该查哪个库（由用户显式选择）
- 不迁移已有评测集（各库评测集独立建设，另行立项）

## 2. 验收标准（Acceptance Criteria）

- [x] AC1：页面顶部出现知识库切换器，列出**所有可用库**（至少 2 个，含当前库）
- [x] AC2：切换后，检索只返回**该库**的文档（跨库文档不出现在结果中）
- [x] AC3：切换后，实体/别名匹配只用该库的词条表
- [x] AC4：切换后，向量检索只用该库的向量索引
- [x] AC5：切换库后清空当前问答，不残留上一个库的答案与 trace（Q4）
- [x] AC6：当前库在切换器上有明确选中态
- [x] AC7：**`file://` 双击打开也能切换**（数据文件按 `?db=` 动态载入），
       仅在服务端不可达时隐藏切换器（无库可切）
- [x] AC8：自检面板显示当前知识库，并说明评测集只对世界杯库适用
- [x] AC9：新增 `tests/test_database_switch.js`，13 项断言通过
- [x] AC10：现有测试全部通过（回归）

**清洗管线说明（档位 A 全自动）**：
`clean_wiki.py` 扫描 Raw，用 `[[词条]]` 反向索引统计出现次数与关联笔记；
描述取该词条首次出现所在的整句（跳过标题行、表格行、引用行与列表符号）。
4 号库原始文档里存在未闭合双链（如 `…数据[[中台]]V2.0…`），写入前统一清理方括号，
避免生成嵌套双链破坏 Wiki 语法。

这是档位 A 的既定取舍 —— 先跑通链路，再看是否对高频词条升级到档位 B/C。
