# SPEC-023 重排 trade-off 调优

> 状态：Plan ｜ 优先级：P2 ｜ 归属：检索层 ｜ 创建：2026-10-24

## 1. 需求（Spec）

SPEC-005 上线后有一个明确退步：两道「揭幕战」题从**第 2 名掉出 top-5**。
原因是 cross-encoder 对**内容更丰富**的干扰文档打分偏高 ——
文档越详细，模型越觉得"相关"，但真正的答案其实在更简短的文档里。

## 2. 验收标准（AC）

- [ ] AC1：两道「揭幕战」题回到 top-5
- [ ] AC2：总体 Hit@1 不低于 79.2%，Hit@5 不低于 97.5%
- [ ] AC3：调优手段可解释（不是调参凑数）

## 3. 候选方案（待评估）

| 方案 | 思路 | 风险 |
|---|---|---|
| A 长度惩罚 | 重排分 ÷ log(文档长度)，抑制长文优势 | 可能误伤确实靠长文命中的题 |
| B 混合分 | 融合分与 rerank 分加权，不让 rerank 独断 | 权重需要重新搜 |
| C 提高候选质量 | 缩小候选集，减少干扰文档进入重排 | 可能漏掉真正的答案 |
| D 标题强信号 | 标题命中查询词时加分（类似 SPEC-006 的思路） | 与实体保护逻辑重叠 |
