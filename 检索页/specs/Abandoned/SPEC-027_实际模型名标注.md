# SPEC-027 页头标注实际回答的模型名（已废弃）

> 状态：**Abandoned** ｜ 优先级：P1 → 废弃 ｜ 归属：前端 / 大模型通道
> 创建：2026-10-24 ｜ 废弃：2026-10-24（真机验证失败）｜ 相关：SPEC-026、SPEC-028

## 1. 原需求

页头只显示 `大模型：Auto`，看不出实际是谁在回答。希望显示为：

```
大模型：Auto（本次回答由“deepseek-v3”提供）
```

依据：OpenAI 兼容的流式响应里，每个 chunk 通常都带 `model` 字段。

## 2. 实现过什么

| 文件 | 位置 | 说明 |
|---|---|---|
| `index.html` | `streamAnswer()` 流循环 | 读取 `chunk.model`，首次拿到即调 `setAi()` 更新页头 |
| `tests/test_llm_speed.js` | 原第 6 节 | 三种场景（路由到别家 / 无 model / model 相同） |

自动化验证当时**全部通过**（mock SDK 里能正确显示
`大模型：Auto（本次回答由"deepseek-v3"提供）`）。

## 3. 为什么废弃（真机结论）

发布后实测：**页头始终为 `大模型：Auto`，从未出现括号标注**。

结论：**该平台不在流式 chunk 里回填 `model` 字段**。
整个功能建立在一个平台未提供的前提上 —— AC1 在真实环境下无法达成。

补充推断：页头一直显示 `Auto`，说明 `models.list()` 的候选里
**只有 Auto 一个可用模型**（否则 SPEC-026 的 `pickModel()` 会把 `auto` 排到最后、
优先选其他模型）。即使平台回填了 model，也只会是 `Auto` 本身，
按 AC2 的规则依然不显示 —— **这条路两头堵死**。

## 4. 处置

- **代码已删除**（`index.html` 流循环里的 `actualModel` 分支，2026-10-24）
- **测试已删除**（`tests/test_llm_speed.js` 原第 6 节）
- 不留死代码：该分支在真实环境下永不可能命中

## 5. 替代方案

| 需求 | 改用 |
|---|---|
| 想知道有哪些模型可选 | **SPEC-028**：`?models=1` 在页面列出完整候选清单 |
| 想固定用某个模型 | **SPEC-026**：`?model=<id>` 强制指定 |

## 6. 附带结论

本项的初衷是排查 SPEC-026 的 94s 生成耗时。废弃它的同一天实测到
**生成耗时已降到 19.7s**，排查动机已消失 —— 即便能显示模型名，收益也很有限。
