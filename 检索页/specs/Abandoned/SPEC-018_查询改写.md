# SPEC-018 查询改写

> 状态：Abandoned ｜ 原优先级：P1 ｜ 归属：检索层 ｜ 归档：2026-10-23

## 1. 原需求

设计方案 v2（第三节）：大模型路由输出的 JSON 里包含 `改写查询` 字段，
把口语化提问改写成更接近原文的说法，再交给检索，提升关键词路的召回。

## 2. 为什么放弃

- 它是 SPEC-017（路由层）的附属字段，路由层整体放弃后失去载体
- 向量路（SPEC-003）已经用更直接的方式解决了同一问题：
  口语化改写型 Hit@5 **77.8% → 91.7%**，不需要额外的改写环节
- 改写会引入二次不确定性：改写错了反而拖累关键词路

## 3. 替代方案

**向量语义检索**（SPEC-003）+ 查询侧指令前缀。
让编码器去对齐语义，而不是让 LLM 去改写字面。

## 4. 教训

两个方案解决同一个问题时，优先选**有量化指标可验证**的那个。
向量路的提升是可测的（+13.9pt），查询改写的收益当时只能靠感觉。
