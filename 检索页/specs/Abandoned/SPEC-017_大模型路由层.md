# SPEC-017 大模型路由层（自动模式）

> 状态：Abandoned ｜ 原优先级：P0 ｜ 归属：检索层 ｜ 归档：2026-10-23

## 1. 原需求

设计方案 v2（第三节）：用户问题先给大模型，由它判断走哪几路检索，
输出 JSON `{route: [...], 改写查询, 命中实体}`。
例：「德国队名单都有谁」→ `entity + keyword`；「哪支队被称为无冕之王」→ `vector`。
不可用时降级为三路并行 + RRF 融合。

## 2. 为什么放弃

| 问题 | 说明 |
|---|---|
| 不可复现 | 同一问题两次调用可能给出不同 route，评测结果无法稳定复现 |
| 不可回归 | 120 题评测要跑 120 次大模型调用，慢且贵，改一次权重就要重跑一次 |
| 无法归因 | 指标掉了，分不清是路由错了还是检索错了 |
| 收益不确定 | 固定权重实测已经很好（Hit@1 64.2% → 72.5%），路由的增量空间未经证实 |

## 3. 替代方案

**固定权重融合**（SPEC-004）：`0.45×关键词 + 0.25×实体 + 0.30×向量`。
三路**都跑**，不做取舍 —— 代价是算三份，收益是稳定、可评测、可解释。

补充手段：
- 实体精确命中保护（SPEC-006）—— 用规则兜住模型的系统性偏差
- trace 面板（SPEC-009）—— 用可视化补上「为什么是这个结果」的解释性

## 4. 教训

在**有量化评测**的场景里，可复现性 > 智能感。
LLM 做路由看起来优雅，但它把「可控的排序问题」变成了「不可控的生成问题」。
