## 一、目标

在知识库之上做一个浏览器端的智能检索页，支持三种检索方式，并提供一个**自动模式**——由大模型判断问题适合走哪一种或哪几种检索，融合后给出结果与答案。

三种方式：
- **关键词检索**：精确词、专名、数字
- **向量检索**：语义相近、换个说法问
- **实体检索**：人物 / 球队 / 概念直接查词条

## 二、环境探测结论（决定技术选型）

| 探测项 | 结果 | 影响 |
|---|---|---|
| 云服务大模型 | 免密钥可用，但**只有对话接口，没有向量化接口** | 语义生成免费用；**向量化要自己解决** |
| huggingface.co / hf-mirror.com | 不可达（000） | 不能用 HF 直拉模型 |
| **modelscope.cn（魔搭）** | **可达** | ✅ 从魔搭下载模型 |
| jsdelivr / unpkg | 可达 | ✅ 前端库走 CDN |
| 语料规模 | 146,438 字（≈ 9.8 万 token），约 300–500 个片段 | 全量本地化，**不需要数据库** |

**选定向量模型**：`Xenova/bge-small-zh-v1.5`（魔搭）
- int8 量化版 `onnx/model_quantized.onnx` = **24 MB**，加分词器约 0.6 MB
- 中文语义检索效果好的小模型，浏览器可直接推理
- 构建时下载并随项目打包，**运行时不再依赖外网**

## 三、总体架构（四层）

```
用户问题
   │
   ▼
路由器（大模型判断走哪几路）
   │
   ├──────────┬──────────┐
   ▼          ▼          ▼
关键词检索   实体检索   向量检索
BM25+二元    词条·别名  bge-small-zh
   └──────────┴──────────┘
   │
   ▼
大模型生成答案（融合排序 · 标注来源）
```

### 1. 数据层（构建时一次性）
- md → 片段（按 `## 小节 + 段落` 切，约 300–500 块）
- `data.json`：每条 `{id, 类型, 标题, 分类, 正文, 关键要点, 关联词条}`
- `keyword-index.json`：中文二元切分（bigram）+ 英文词倒排
- `embeddings.json`：每个片段的向量（bge-small-zh 计算）

### 2. 检索层（三路并行）

| 通道 | 擅长 | 典型提问 | 实现 |
|---|---|---|---|
| 关键词 | 精确词、专名、数字 | 「26人大名单」「7.5亿」 | BM25 + bigram 倒排 |
| 实体 | 人物 / 球队 / 概念直查 | 「梅西」「无冕之王」→ 荷兰 | 词条名 + 别名表精确匹配 |
| 向量 | 口语化、换说法 | 「哪支队被叫无冕之王」 | bge-small-zh 余弦相似 |

### 3. 路由层（自动模式）
- 大模型收到问题 → 输出 JSON：`{route: [...], 改写查询, 命中实体}`
- 例：「德国队名单都有谁」→ `entity + keyword`；「哪支队被称为无冕之王」→ `vector`
- **降级策略**：大模型不可用时，三路并行 + RRF 融合，页面照常可用

### 4. 生成层
- top-k 片段 → 大模型流式生成答案 + 标注来源笔记

## 四、页面结构

- **顶部**：搜索框 + 模式开关（自动 / 关键词 / 向量 / 实体）
- **左栏**：类型筛选（笔记 / 实体 / 概念）+ 分类筛选
- **中间**：AI 答案卡（流式）+ 结果卡片（命中高亮）
- **右侧**：词条详情 / 笔记原文，含关联跳转

## 五、技术栈

- 单页 HTML + 原生 JS，**无构建步骤**
- transformers.js（jsdelivr CDN）+ 本地 bge-small-zh 模型
- 大模型：WorkBuddy 云服务（免密钥，首次使用需开通）
- 数据产物：`data.json` / `keyword-index.json` / `embeddings.json` / `models/`

## 六、性能预估

| 环节 | 耗时 |
|---|---|
| 关键词检索 | < 10 ms |
| 向量检索（查询编码） | 100–300 ms |
| 大模型路由 + 生成 | 1–3 s（流式） |
| 首次加载 | 模型 24 MB（之后浏览器缓存） |

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 24 MB 模型拖慢首屏 | 首屏先用关键词可用，模型后台加载；就绪后自动开启向量路 |
| `file://` 打开无法 fetch 模型 | 提供本地启动脚本（`python -m http.server`），或直接走线上链接 |
| 大模型需开通云服务 | 首次调用时由 WorkBuddy 弹窗确认开通 |
| 模型源不稳定 | 构建时下载并打包，运行时不依赖外网 |
| 大模型输出不可信 | 答案只基于检索片段生成，强制标注来源，不执行模型输出 |
